## 一、Java / Spring 后端

### 1. 环境与配置

**环境变量与取值优先级**
- 环境变量是 OS 层 key=value，Java 用 `System.getenv()` 读。
- Spring `${DB_URL}` 取值优先级：命令行 > 系统属性(`-D`) > 环境变量 > application 配置 > 默认值。
- 环境变量加载自动（systemEnvironment PropertySource），`${DB_URL}` 占位符自动解析，零代码。
- 宽松绑定：`DB_URL` ↔ `${DB_URL}`；`SPRING_DATASOURCE_PASSWORD` ↔ `spring.datasource.password`。
- `.env` 文件不自动加载：`.env.local` 不是 OS 环境变量，需 DotenvInitializer 手动注入。
- 注意：环境变量启动时读一次，改完要重启；`${DB_URL}` 无默认值且未提供 → 占位符原样保留（报 `jdbcUrl: ${DB_URL}`）。

**mvn 命令行**
- `clean` 删 target / `compile` 编译并复制 resources 到 target/classes / `package` 打包。
- `spring-boot:run` 运行；`-pl <模块>` 只编某模块。
- 注意：改了 src 配置必须重新 compile 才生效（跑的是 target/classes 里的配置）。

**Spring profile 机制**
- `application.yml` 永远加载（基础）；`spring.profiles.active: dev` 激活 profile，额外加载 `application-dev.yml`。
- 同名 key 覆盖基础；用途是一套代码多套环境（dev/prod/qa）用 profile 切换。
- 覆盖优先级：命令行 > 系统属性 > 环境变量 > application-dev.yml > application.yml。
- 多个 application 是字段级合并（不整个文件替换）；可放多个 `application-{env}.yml`，active 指到谁加载谁。
- 坑：dev 里 `url: ${DB_URL}` 无默认值，覆盖掉基础默认值 → 必须外部提供。

**gitignore 原则**
- 含真实密钥/密码/地址的不进 git；模板和默认值可进。
- `application.yml` 进；`application-{env}.yml` 含真实密码应 gitignore 或改占位符。
- `.env.local` 必须 gitignore；`.env.example` 进。

### 2. 注解与依赖注入

**常用注解**
- `@Override` 重写方法 / `@Deprecated` 标记废弃 / `@SuppressWarnings` 忽略警告 / `@Component` 注册组件。
- `@Autowired` 依赖注入按类型；`@Resource` 依赖注入按变量名。
- `@RestController` = `@Controller` + `@ResponseBody`（Web 控制器）。
- `@Configuration` + `@Bean` 声明配置类、注册方法；`@XXXMapping` 路由映射。
- `@Data`（Lombok）自动生成 getter/setter；`@Slf4j` 日志。

**依赖注入建议**
- 团队规范用 `@Resource` 注入依赖（按变量名）。

### 3. 异常处理

- `@RestControllerAdvice` 捕获控制层异常，`@ExceptionHandler` 通过异常类型捕获并处理。
- 局限：只能捕获 controller 请求处理链的异常；另开的线程和 SSE 链接中的异常无法被捕获。
- 自定义异常类型处理：如 `MethodArgumentTypeMismatchException`（PathVariable 参数类型不匹配）。

### 4. SpringBoot 组成与请求链路

**组成**
- Tomcat：servlet 容器，接收 HTTP 请求、解析协议、管理线程池。
- DispatcherServlet：SpringMVC 的"前端控制器"，按 URL 路由到 Controller。
- Filter 过滤器链：请求进入业务前做通用处理（跨域 CORS、编码）。
- AOP：不改业务代码织入通用逻辑（日志、事务）。
- 分层：Controller（接收/校验）→ Service（业务逻辑）→ Mapper（SQL）。

**请求链路**
- HTTP → Tomcat → Filter 链 → DispatcherServlet（HandlerMapping/拦截器/参数解析）→ Controller → Service → Mapper → MySQL。
- 返回逆向传回，DispatcherServlet 转 JSON 或视图。

**Servlet Filter 过滤链细节**
- 请求 → Servlet 容器 → Filter 链 → DispatcherServlet → HandlerInterceptor → AOP → Controller。
- 每个 Filter 调 `filterChain.doFilter()` 才放行，不放行就截断。
- HandlerInterceptor 和 AOP 不在 Servlet 过滤链里，是 Spring MVC/AOP 层环节。
- 配置三种方式：`FilterRegistrationBean`（@Bean、setUrlPatterns/setOrder）、`@Component`/`@Bean` 注册、继承 `OncePerRequestFilter`（一次请求只执行一次）。
- 共享数据：`SecurityContextHolder`（认证上下文）、`HttpSession`（会话级）、`HttpServletRequest.setAttribute`（请求级，`@RequestAttribute` 取）。

### 5. Spring 生态组件

- Feign：SpringCloud 声明式 HTTP 客户端，接口+注解声明请求，框架自动生成实现。
- MetaObjectHandler：MyBatis-Plus 元对象处理器，配合 `@TableField(fill=FieldFill.INSERT)` 自动填充创建/更新时间。
- ResponseEntity：完整 HTTP 响应对象（状态码+头+体），`ResponseEntity.ok()/status()` 构造，比直接返回对象灵活。
- SecurityConfig：`@Configuration` + `@EnableWebSecurity`，配 SecurityFilterChain 认证/权限/BCrypt 密码/CSRF。
- MybatisPlusInterceptor：注册 InnerInterceptor（如分页 PaginationInnerInterceptor），SQL 执行前后织入逻辑。

### 6. MyBatis-Plus 使用

**分层**
- Mapper 接口继承 `BaseMapper<Entity>`。
- Service 接口继承 `IService<Entity>`，实现类继承 `ServiceImpl<Mapper, Entity>`。

**常用方法**
- 插入 `insert`；删除 `deleteById`、`deleteBatchIds`、`deleteByMap`、`delete(wrapper)`。
- 更新 `updateById`（只更新非 null）、`update(entity, wrapper)`。
- 查询 `selectById`、`selectBatchIds`、`selectOne`（多条报错，用 `.last("limit 1")` 兜底）、`selectCount`、`selectMaps`、`selectList`、`selectPage`。
- Service 层：`save/saveBatch`、`removeById/remove`、`updateById/update`、`getById/getOne/list/count/page`。
- Service 层直接用 `lambdaQuery()` / `lambdaUpdate()`。

**条件构造**
- `LambdaQueryWrapper` 条件方法：`eq/ne/gt/ge/lt/le/like/in/between/isNull/orderByDesc`。
- 多条件用 `and(...)` / `or(...)` 包内层。
- 动态条件：wrapper 第一个参数是 boolean condition，false 时跳过。
- 推荐 Lambda 版（方法引用，编译期检查，字段改名不破）。

**自定义方法与返回结构**
- Mapper 加方法，`@Select`/`@Insert` 等写 SQL 或配 XML；`@Param("ew")` 接 wrapper，`${ew.customSqlSegment}` 复用条件。
- 返回结构方式 1：resultMap 映射到 DTO/VO（`<id>/<result>` 列映射，一对一 `<association>`、一对多 `<collection>`，嵌套后列名要别名区分）。
- 返回结构方式 2：`selectMaps` 返回 Map，在 Service 层组装。
- 返回结构方式 3：`${ew.customSqlSegment}` 复用 MP 条件。
- 注意：`${}` 是字符串拼接有注入风险，只拼 `ew.customSqlSegment`（内部已参数化），别拼用户输入。

## 二、JVM 与 Java 底层

**字节码与执行机制**
- `.java` 经 javac 编译成 `.class`（JVM 指令集，平台无关）→ 每个平台 JVM 翻译成本地机器码。
- 解释器逐条翻译，启动快但慢；JIT 统计热点方法整段编译成机器码缓存，越跑越快（混合执行）。
- GraalVM Native Image（AOT）跑时不需要 JVM。

**JVM 上其他语言**
- ASM（字节码操作库，Spring 动态代理/CGLIB/Lombok 背后）。
- Jython、Groovy（Gradle 构建脚本常用）、Kotlin（Android 官方）。

**堆和栈**
- 堆：最大，`new` 的对象/数组，线程共享，GC 管理，可扩容。
- 栈（虚拟机栈）：每线程私有，一串栈帧（局部变量、操作数、返回地址），方法结束弹出；递归过深抛 `StackOverflowError`。

**类加载解析（resolve）**
- 符号引用（类名/方法名字符串）→ 直接引用（实际内存地址）。

**垃圾回收器**
- JDK17 默认 G1。
- 常用：Serial（单线程）、Parallel（吞吐优先，JDK8 默认）、G1（区域化、可预测停顿，JDK9+ 默认）、ZGC（毫秒级停顿，超大堆）、Shenandoah；CMS 已移除。
- 分代收集：年轻代（Eden+两个 Survivor）标记-复制；老年代标记-清除/整理。
- 取舍：要吞吐量选 Parallel，要低延迟选 G1/ZGC。

## 四、前端 / Vue3

**组件拆分与目录约定**
- `index.vue` 页面入口负责组装子组件；`components/` 放子组件。
- `composables/` 放 useXxx 可复用逻辑；`utils/` 放纯函数；`const.ts` 放常量；`types/` 放类型；`mock/` 放假数据。
- 一个 vue 文件 = template（结构）+ script setup（逻辑）+ style（样式）。

**组件通信**
- 父传子：`<Child :runs="runs" />`，子 `defineProps<{ runs: Run[] }>()`；单向数据流，子不能改 props。
- 子传父：子 `defineEmits<{ change: [val: string] }>()` 某时机 `emit('change', val)`，父 `@change="fn"`。
- 数据共享：`v-model` + `defineModel`，本质是 `defineProps(modelValue)` + `defineEmits(update:modelValue)` 语法糖。

**响应式与 key**
- `v-for` 必须绑 key：diff 靠 key 判断是否同一节点，决定复用/重建。
- 用 index 当 key 在插入/删除/排序时会状态串行。
- 动态组件(`:is`)、transition-group 也要 key。

**请求（axios）**
- 请求配置：url/method/params/data/headers/timeout/responseType/baseURL；响应：data/status/headers。
- 进度回调：onUploadProgress/onDownloadProgress（total 可能为 0，先判空）；validateStatus 自定义成功状态码。
- 取消：AbortController 的 signal（或旧 CancelToken）；取消后 promise reject，error 是 CancelError，用 `axios.isCancel(error)` 判断。
- silent 自定义标记：标记请求出错时不弹全局提示（由调用方处理），拦截器里判断 `!error.config?.silent`。
- 全局钩子：interceptors.request.use/response.use 统一加 token、统一处理错误。

**Element Plus 常用组件**
- el-table：`:data` 绑数组，el-table-column 列（prop/label/width/min-width/align），`#default="{ row }"` 拿当前行，stripe/size/border/empty-text。
- el-card：slot `#header` 标题，默认 slot 内容，`shadow="never"` 去阴影，`--el-card-*` 变量覆盖样式。
- el-tabs：`v-model` 绑激活 name，el-tab-pane（label/name），`type="border-card"`，`:deep(.el-tabs__content)` 调样式。
- el-collapse：`v-model` 绑数组（可多开）或字符串（accordion 单开），`@change` 触发。
- RecycleScroller：虚拟滚动，只渲染可视区+缓冲区，滚动复用 DOM，要求固定 item-size。

**样式**
- BEM 命名：`.block--element` / `.block__modifier`。
- CSS 变量：`:root` 定义 `var(--x)` 取用；内层重定义覆盖；element-plus 用 `--el-xxx` 覆盖组件样式。
- `:deep`：scoped 会给选择器加 data 属性，子组件内部 DOM 匹配不到，用 `:deep(.xxx)` 穿透。
- 设计技巧：同色相明度/饱和度分层、间距用 4 的倍数、浅阴影+圆角、渐变/毛玻璃、hover 微交互。

**其他 JS 知识点**
- 可枚举/不可枚举：enumerable 决定属性是否被 for...in/Object.keys()/JSON.stringify 看到；`Object.defineProperty` 创建的默认不可枚举。
- `JSON.stringify`：只序列化可枚举自有字符串属性；undefined/函数/symbol 忽略；循环引用报错；有 `toJSON()` 用它。
- 正则：`\d/\w/\s/^$/[]/|/()/量词{}/修饰符 gims`；test/match/replace/search/split；反向引用 `\1`。
- fetch-event-source：onopen（连接建立）/onmessage（每条 SSE 数据）/onclose（正常关闭）/onerror（异常，返回毫秒数=延迟重连，非正数=停止）。

**流程**
- 前端列表页建 SSE 链接 → 后端接收请求，进行 sweep → sweep 每完成一个 run 循环就调用 SSE 工具类广播 → 前端接收信息改 store → 触发响应式更新。

## 六、Docker 与 Linux

**Dockerfile 语法**
- 构建镜像脚本，每条指令生成一层：FROM（基础镜像，必须第一行）、WORKDIR、COPY/ADD（拷文件）、RUN（构建时执行）、ENV、EXPOSE（声明端口，映射靠 -p）、CMD（启动命令可覆盖）、ENTRYPOINT（不可覆盖）、ARG。
- 层可缓存：不常变的放前面、常变的放后面加速构建；`.dockerignore` 排除 node_modules/target。

**docker-compose**
- YAML 编排多容器：services 定义，字段 image/build、ports（"宿主机:容器"）、volumes（持久化）、environment、depends_on（启动顺序）、restart。
- 命令：`docker-compose up -d` / `down` / `logs -f` / `ps`。

**Linux 基础**
- 目录：/etc 配置、/var/log 日志、/home 用户、/tmp 临时、/usr/local 自装软件。
- 常用命令：cd/ls/pwd/mkdir/rm/cp/mv；ps/top/df -h/ss（端口）/tail -f/chmod/systemctl/tar/grep/find。

**何时重新 build**
- Dockerfile 每条指令只在 docker build 时执行一次；运行时只执行 CMD/ENTRYPOINT。
- RUN 构建时执行（如 `RUN mvn package` 产物打进镜像）；CMD 每次启动执行。
- 改了代码/依赖/配置/Dockerfile 后要 rebuild；改依赖建议 `--no-cache`。
- 开发时 `docker run -v` 挂载代码目录可热更新，不用每次 rebuild；生产要 rebuild 打包。

## 七、Git

**对象模型**
- 内容存成 blob（文件内容）/tree（目录）/commit 三层对象，SHA-1 哈希唯一标识，改一个字节哈希就变。
- 暂存区（index）存 blob 哈希指针。

**分支领先落后**
- 先找最近公共祖先 `git merge-base A B`；领先/落后数 = `git rev-list --left-right --count A...B`。
- 直观查看：`git status -sb` 或 `git branch -vv`。

**合并冲突**
- 冲突 = 两边都改了同一区域且改得不一样（三方合并 base/ours/theirs）；只一边改/改不同区域/不同文件自动合并。
- "同一区域"是 diff 的 hunk 行范围 `@@ -旧,旧 +新,新 @@`，不是单行号。

**常见场景命令**
- 放弃合并 `git merge --abort`（rebase 用 `--abort`）；解决冲突：删 `<<<<<<<` 标记 → git add → merge 用 commit、rebase 用 `--continue`。
- 改提交信息 `git commit --amend`；漏文件 git add + `--amend`；撤销暂存 `git restore --staged`（旧版 `git reset HEAD`）。
- 放弃本地改动 `git restore`（旧版 `git checkout --`）；误提交保留改动 `git reset --soft HEAD~1`；`reset --hard` 丢了用 `git reflog` 找回。
- 切分支有未提交 `git stash` → 切换 → `git stash pop`；push 被拒 `git pull --rebase` 再 push；已推送别 reset 用 `git revert`。
- 挪 commit `git cherry-pick`；误删分支 `git reflog` 找 commit 重建；多个提交合并 `git rebase -i` 改 squash。

**merge vs rebase**
- merge：保留历史分叉、产生合并提交，安全，适合公共分支。
- rebase：重写历史、线性整洁，适合本地整理未推送提交，别对已推送的公共分支用。

## 八、AI Agent 原理

**Agent 怎么工作**
- Agent = 大模型 + 工具 + 循环：收到任务 → LLM 规划 → 调工具（读文件/跑命令/搜索）→ 工具结果放回上下文 → 继续推理 → 直到完成。

**多 Agent 并发**
- 每个 Agent 独立进程/会话，各自维护上下文和工作目录，并行跑自己的循环。
- 共享资源靠文件锁、git worktree 隔离、配额上限控制。

**工具机制**
- 工具是宿主注册给模型的外部函数：函数描述（名字+参数 schema）通过工具列表告诉模型。
- 模型声明"调用 toolX(参数)" → 宿主执行 → 结果返回上下文；模型只请求调用，宿主执行。
- 模型靠系统提示里的 tools 知道有哪些工具，推理时自己决定调用哪个（function calling / tool use）。

**skill 是什么**
- 预打包的指令/流程（如 Claude 的 `.claude/skills/` 下的 md），按需加载进上下文。
- 作用：把某类任务的专家流程固化成可复用操作手册。

**skill vs RAG**
- skill 是"怎么做"（过程/指令）；RAG 是"用什么资料"（按需检索文档片段塞进上下文）。
- 可结合：skill 定流程，RAG 供资料。

**上下文与记忆**
- 上下文（context window）= 模型一次看到的全部（系统提示+对话历史+工具结果+文件内容）；对话是外部记录，上下文是其中窗口内部分。
- 接近上限时 compact：把早期内容压缩成摘要，只保留最近完整内容，所以"迟迟不到上限"。
- compact 是有损压缩，越久远越细节的信息丢失越多；具体缺失率各家没公开数字。

**感知项目/IDE**
- 插件/扩展通过 VS Code 扩展 API 显式读取工作区目录、打开的编辑器文件、文件系统、Git 状态；不是魔法。
- 大模型的目录结构是宿主通过 ls/glob/读文件等工具喂给它的，模型只知道它能读到的。

**中断恢复**
- 一般在关键节点持久化状态（保存对话/写到文件/记录步骤），恢复时接着做；没存状态才从头开始。

## 九、Transformer / 大模型原理

**计算过程、参数 vs 权重**
- Transformer = 输入向量过 N 层块，每块 = 多头自注意力 + FFN，各配残差 + LayerNorm；计算全是"输入 × 权重矩阵 → 线性变换 → 非线性"。
- 参数 = 所有可学习数字（模型大小）；权重 = 具体矩阵的数值。
- 主要参数：Embedding、注意力 Q/K/V 投影 + Wo、FFN 两层 W1/W2、LayerNorm 的 γ/β。
- 一层流程：Q=X·Wq / K=X·Wk / V=X·Wv → score=softmax(Q·Kᵀ/√d)·V → Wo → 残差+LN → FFN（W2·GELU(W1·x)）→ 残差+LN。

**CNN vs Transformer 的参数参与**
- CNN 用小卷积核在输入上滑动窗口乘加（局部共享）。
- Transformer 用大矩阵全连接线性变换（全局共享），靠注意力对不同位置动态加权。
- 注意力加权：Q·Kᵀ 算相关度 → softmax 成权重 → 乘 V 加权求和；组合方式由内容决定。

**上下文怎么保存**
- 没有显式记忆，靠两样：历史 token 编码进 attention 一起算，新 token 通过注意力"看到"前面全部；KV Cache 缓存已处理 token 的 K/V 到显存，下一个复用。
- 上下文窗口 = 能容纳的 token 数，受显存限制；超限压缩/截断（RoPE、滑动窗口、稀疏注意力扩展）。
- KV Cache 是上下文长度的主要内存消耗：每多一个 token，所有层要多存一行 K/V。

**怎么预测下一个词**
- 最后一层 × 词表投影矩阵 lm_head（≈ Embedding 转置）→ logits → softmax 成覆盖整个词表的概率分布 → 取最高或采样（自回归，逐词生成）。
- "存进矩阵" = 下一词通过嵌入矩阵查表得向量，追加到序列末尾当下一轮输入。

## 十、工程实践 / 私有化部署

**私有部署 AI 是最大麻烦吗**
- 是必要前提（数据不能出内网）但只是麻烦之一。
- 真正大麻烦是三件套：模型私有化部署（GPU/显存/推理框架 vLLM/TGI）；框架与内部系统整合（认证权限/运维/幻觉与 prompt 注入安全）；数据合规驱动。
- 排序：模型部署是起步最大硬门槛；部署完后框架整合、权限安全、效果调优是持续大麻烦。

**开源框架接内网 AI**
- 可以，主流做法：框架配置 base URL 指向内网模型服务（vLLM/TGI/Ollama），请求不出内网；前提是框架支持自定义端点或 OpenAI 兼容 API。
- 能用 ≠ 好用：内网模型要支持 function calling（选 Qwen/GLM 等）；账号/权限对接公司系统；确认请求只走内网。
- 坑：很多框架默认绑云 API 要改配置/源码；内网模型效果、上下文长度、function calling 稳定性决定实际好不好用。

## 十一、软技能 / 方法论

1. 金字塔原理：结论先行，上下对应，归类分组，逻辑递进。

2. 项目时间占比：设计 50%、编码 20%、部署调试 30%。

3. 标准过程做标准：先定义标准的产生流程和规范，再按流程产出可执行标准，保证一致可复用。

4. 系统三要素：组成要素（岗位/角色/原材料）、要素间关联（关系/流程）、系统存在目的；分析系统 = 回答"有哪些要素、怎么关联、为什么存在"。

5. 需求拆解
   - 分清需求与解决方案：用户说的往往是解决方案（"我要番茄牛肉盖饭"），背后需求是"我饿了"；解决方案可多变，需求才稳定。
   - 需求分类：软件（功能+非功能）、硬件、机械、电气，不能只盯着软件。
   - 描述需求用"强动词+名词"（"系统应支持保存用户信息"），避免"处理/管理"这类笼统词。

6. 业务分析四维：角色（谁参与）、领域（范围术语）、流程（怎么流转）、规则（约束）；业务分经营性（直接创造价值）和非经营性（支持/管理）。

## 二、🔴 严重问题（16 项）

### 运行时必坏（最高优先）

**S1. 加歌到队列必报 500（MyBatis BindingException）**
- 位置：`backend/src/main/java/com/kyf/mp/server/modules/queue/business/imp/QueuesBusinessImpl.java:300,308` 调用 `moveItemPositionsToTemporary` / `restoreShiftedItemPositions`；接口声明 `mapper/QueueCustomMapper.java:26,28`；但 `queue/xml/QueueCustomMapper.xml` 中**没有这两条语句**（只有名字相近的 `moveAllItemPositionsToTemporary`）。
- 影响：任何"添加歌曲到队列"操作首次执行即抛 `BindingException`，功能不可用。
- 修复方向：在 XML 补两条 `<update>`（把 `queue_item_position >= #{pos}` 临时后移/恢复），或在接口上用注解 SQL。

**S2. 从歌单建队列在新库上必失败（缺主键列）**
- 位置：`queue/xml/QueueCustomMapper.xml:82` `INSERT INTO queue_items (queue_id, song_id, queue_item_position) SELECT ...`；`db/migration/V1__initial_schema.sql:116` 中 `queue_item_id` `NOT NULL` 无默认值。
- 影响：全新 Flyway 库上「播放全部/从歌单创建队列」报 NOT NULL 约束错误（旧库若建过表同样失败，除非 MySQL 非严格模式）。
- 修复方向：改为应用层逐条插入（MyBatis-Plus ASSIGN_ID 生成雪花主键），或 SQL 中显式生成 ID。

**S3. 登录日志泄露完整 JWT**
- 位置：`modules/user/service/imp/UsersServiceImpl.java:65`：`log.info("===> 业务逻辑执行完毕，准备返回: {}", vo)`，`vo` 是含 token 的 `LoginVO`。
- 影响：token 落入日志系统可致账号劫持。
- 修复方向：改为 `log.info("login ok userId={}", user.getUserId())`，全链路日志脱敏。

### 认证与访问控制

**S4. 401 后登录回弹循环（到不了登录页）**
- 位置：`web/src/api/axios.ts:131-145` 401 分支只清 localStorage、**不清 Pinia 内存态**；`web/src/router/index.ts:110` `requiresGuest && isAuthenticated` 把用户从 `/login` 弹回 `/`。
- 影响：token 过期后用户被"踢回"原页面而非登录页，UI 仍显示已登录，所有请求持续 401。
- 修复方向：401 时同步重置 user store（注意 axios↔store 循环依赖，建议用事件或延迟导入）；router 守卫改用 token 存在性判断。

**S5. 播放模式循环永回不到「顺序播放」**
- 位置：`web/src/components/player-control/composables/use-play-mode.ts:11-15` + `const.ts:2`：`PLAY_MODES` 数组只有 `repeat_all/repeat_one/shuffle`，缺 `sequential`，且 sequential 被映射成 repeat_all。
- 影响：首次切换后顺序播放永远回不来。
- 修复方向：数组补 `sequential`，切换逻辑直接用当前值索引。

**S6. 歌单建队列 IDOR + `is_public` 零使用**
- 位置：`modules/queue/business/imp/QueuesBusinessImpl.java:231` 只 `selectById(playlistId)` 不校验归属/可见性；`modules/playlist/business/imp/PlaylistsBusinessImpl.java:187-223` 详情不校验 `is_public`；grep 实测 `is_public` 全项目无任何业务逻辑使用。
- 影响：任何登录用户可复制他人私密歌单内容；私密歌单形同虚设。
- 修复方向：建队列前校验 `creatorId==userId || is_public`；详情接口同样处理。

**S7. 访客被强制跳登录（公开页面不可用）**
- 位置：`web/src/api/axios.ts:131-144` 401 分支无视 `silent` 无条件清 token 并 `router.push('/login')`；`QueueDrawer` 全局挂载（`App.vue`）即拉取 `/queues/current`（未登录 401）。
- 影响：未登录用户访问首页/歌曲库/歌单页会被弹回登录页；`redirect` query（axios.ts:140 写入）不被 `Login.vue:73` 消费，登录后永远跳首页。
- 修复方向：401 处理区分"带 token 失效"与"匿名请求"；匿名请求静默返回；登录后消费 `redirect`（需校验同源防开放重定向）。

### 前端功能缺陷

**S8. 上传仍受全局 5 秒超时**
- 位置：`web/src/api/axios.ts:61` `timeout: 5000`；`song-api.ts` upload 未覆盖。
- 影响：实测 `static/songs/` 已有 11MB+ 文件，后端限 10MB，大文件上传 5 秒必超时。
- 修复方向：上传类请求单独 `timeout: 0` 或 5 分钟；后端限制同步放宽。

**S9. FormData 去重 key 恒 `{}` 导致请求互杀**
- 位置：`web/src/api/axios.ts:41-47`：`JSON.stringify(config.data)` 对 FormData 恒为 `{}`。
- 影响：同 method+url 的两次上传互相 abort；相同参数 GET 并发互杀。
- 修复方向：data 为 FormData 时不参与 key（或附加文件元信息）；相同 GET 不去重或仅对写请求去重。

**S10. 编辑上传页硬刷新失效**
- 位置：`web/src/views/song/edit-upload/EditUpload.vue:126-139` 只读内存 `songStore.currentEditingSong`；无后端"按 ID 查歌曲详情"接口回填。
- 影响：硬刷新/直链进入后标题封面丢失，必填校验导致无法保存。
- 修复方向：新增 `GET /api/songs/my-uploads/{id}`（或 `/api/songs/{id}`）并在页面加载时回填。

### 后端数据正确性

**S11. 扫描器开启 remove-missing 时目录缺失仍清空整表**
- 位置：`utils/SongScannerTask.java:75-99`：`dir.listFiles()` 为 null（目录不存在/未挂载）→ `localUrls` 空 → `idsToDelete`=全部歌曲。
- 影响：显式开启 remove-missing 且卷未挂载时，启动即清空 songs 表。
- 修复方向：`files == null` 时 `log.warn` 直接返回，不进入删除分支。

**S12. playmode 静默丢失 + 契约不一致**
- 位置：`QueuesBusinessImpl.java:461-469` `mapDtoToEntity` 不写 `playmode/isPlaying`；DB 默认 `sequence`（V1:90）vs 前端 `sequential`（`player.ts:25`、`player-control/const.ts:6`）。
- 影响：播放模式无法通过状态同步接口保存（前端传值被静默丢弃）；字符串契约不一致。
- 修复方向：补全映射 + 统一枚举值（后端校验值域）。

**S13. `PlaylistSummaryVO.createdDate` 类型错配**
- 位置：`modules/playlist/vo/PlaylistSummaryVO.java:15-16`（`String` + `@JsonFormat`）；`service/imp/PlaylistsServiceImpl.java:64-68` 用 `BeanUtils.copyProperties`。
- 影响：LocalDateTime 拷不进 String，「我的歌单」列表创建时间恒 null。
- 修复方向：字段改 `LocalDateTime`。

**S14. `/users/cover` 返回键名错位（头像链路整体不可用）**
- 位置：`UsersServiceImpl.java:119` 返回 Map key `"userCoverUrl"`（camelCase；Jackson 不会重命名 Map 键），前端 `user-api.ts:48` 读 `res.data.user_cover_url` → 恒 undefined。
- 叠加：`UserVO` 不含 `user_cover_url`；`types/index.ts:17` `IUser.user_cover` 字段对不上；`NavBar.vue:16` 用 `user.user_cover`（恒空）；`stores/user.ts:58` `fetchUserCoverUrl` 未导出、仅登录后调用一次。
- 修复方向：Map key 改 `user_cover_url`（或返回 VO）；登录/详情响应带 `user_cover_url`；统一前端字段名；登出与刷新时同步处理。

**S15. `PlayState.userId` 仍是 `IdType.ASSIGN_ID`**
- 位置：`modules/queue/entity/PlayState.java:26`。
- 影响：userId 为空时 MP 生成雪花主键，污染以用户为键的播放状态行。
- 修复方向：改 `IdType.INPUT`（或 `NONE`）。

### 仓库与历史

**S16. Git 历史未清理，密钥可恢复 + 仓库膨胀**
- 实测：`git log -S [REDACTED] --all` 命中 9 个提交；`git log -S 88bada62… --all` 命中 7 个提交（HEAD 已清，历史可恢复）；`.git` 目录 **1.1GB**（最大 blob `server/static/songs/魔王魂.mp4` 15MB，另有大量旧 Flask 时代 `server_py/static/` 图片）。

- 影响：任何有仓库读权限者可取回密钥（若旧值仍被使用，可伪造 JWT/直连数据库）；clone 成本高。
- 修复方向：轮换密钥；`git filter-repo`/BFG 清理历史大文件与密钥（重写哈希，需 force-push 决策，README 重构历程中的旧 commit 引用需同步更新）；`.gitattributes` 补 binary/LFS 规则。

## 三、🟠 中等问题（36 项）

### 后端（16 项）

1. **`AccessDeniedException` 返回 500 而非 403**：`common/GlobalExceptionHandler.java:82-87` 兜底吞掉控制器内抛出的该异常。建议单独 handler。
2. **登录枚举 + 无防爆破**：`UsersServiceImpl.java:45-50` 区分「账号不存在/密码错误」；无登录限流。建议统一文案 + 频率限制。
3. **注册竞态未捕获**：`UsersServiceImpl.java:84-103` count-then-save 非原子，并发同名/同邮箱触发唯一约束 500。建议捕获 `DuplicateKeyException` 转 409。
4. **客户端 SHA-256 哈希即凭据**：`web/src/utils/crypto.ts` + `UsersServiceImpl.java:69-81 matchesPassword`——legacy 明文 SHA-256 分支与新 BCrypt(sha256hex) 双语义长期并存，哈希可重放。建议逐步迁移至 HTTPS 明文 + 服务端 BCrypt/Argon2。
5. **歌单详情返回完整歌词且无排序**：`PlaylistsBusinessImpl.java:198-199` 未排除 `lyrics/t_lyrics` 大字段（与 `GetSongsVO` 注释"不含歌词"相反）；`SongsPlaylistsRelationMapper.java:14-16` 无 `ORDER BY song_playlist_position`，展示顺序无保证。
6. **队列上限逻辑失效/悬空**：`QueuesBusinessImpl.java:350-357` `latest != null` 提前 return 使 5 队列上限分支不可达；`:225-229` `createQueueFromPlaylist` 删最旧队列不检查是否当前队列 → `play_state` 悬空。
7. **计数字段无强一致**：`song_count/like_count` 靠代码 ±1 维护（`setSql` 片段），与关系表无事务级一致保障。

10. **`editUserProfile` 无事务**：`UsersBusinessImpl.java:33-86` 文件写入与 DB 更新不原子；改名不复查唯一性（撞约束 500）。
11. **DTO 遗留**：`EditSongDTO.t_lyrics` 死字段；`EditUserDTO/EditSongDTO` 用下划线字段名。
12. **SongScannerTask 残留**：`fileMd5` 是 `Objects.hash(文件名+大小)` 假指纹（`:146`）；`uploaderName` 硬编码 `"SystemScanner"`（`:149`）；删除不按 `uploader_id` 过滤（会把非扫描器录入的歌曲一并删掉）；`@Async` 无 `@EnableAsync`，实际同步阻塞启动。

14. **音频上传无魔数校验**：`UploadFileValidator.java:14-17` 仅扩展名+Content-Type（两者皆客户端可控）；白名单已阻断 html/svg，但建议用 jaudiotagger 读取兜底。

### 基础设施（10 项）

27. **`Docker-compose.yml` 大写 D 不被自动发现**：compose 默认识别列表不含该文件名——Windows（大小写不敏感）侥幸可跑，Linux/CI 上 `docker compose up` 报 no configuration file。建议改名 `compose.yml`（或 `docker-compose.yml`）并同步 README。

30. **健康检查缺口**：backend/nginx 无 healthcheck；nginx `depends_on: - backend-server` 无 `condition: service_healthy`，只等容器启动不等就绪。
31. **compose 安全**：db `3306:3306` 全接口暴露、后端仍以 root 连接；未传 `X-Forwarded-Proto`；nginx 无安全头（nosniff/CSP/HSTS）/HTTPS/限流。
